## 1. 项目是什么

柔性视觉供料系统的**上位机**（Qt Widgets 桌面程序），通过 **RS485 串口或 TCP(以太网)** 控制下位机完成三类动作：

1. **振动盘运动**：9 种动作（上/下/左/右/聚拢/水平居中/垂直居中/振散/翻面），由按钮参数（电压/频率/时间/角度偏移/速度系数）驱动；
2. **料仓运动**：电压/频率/时间三参数，语义与振动盘一致——**下位机运动完成后才回帧**；
3. **光源控制**：A/B 两路光源，各自有亮度(0~100)与保持时间，**开启后 1s 内必须收到下位机完成反馈**。

下位机固件在同仓库 `FlexControlSTM32/` 子目录（STM32F103C8/B + W5500 以太网，HAL 库，MDK-ARM 工程），应用层在 `FlexControlSTM32/Application/`（FlexControl / MotorControl / Network / SerialHandle / Timer / W5500）。

## 2. 源码结构与职责

| 文件 | 职责 |
|---|---|
| `ProtocolHandle.h` | 协议抽象基类（QObject）。定义 `GeneralMotion::MotionParams`（运动索引枚举含 `MotionBin`）+ 各指令的组帧虚函数。新增指令先在这里加虚函数（给默认空实现即可） |
| `generalprotocol.h/.cpp` | 唯一实现类 `GeneralProtocol`（单例）。帧头尾常量、指令码常量、`AddCheckSum`、各协议的"发送帧 + 期望应答帧"成对生成 |
| `ConnectiveHandle.h/.cpp` | **通信引擎**（与传输方式无关）：按指令类型分队列、10ms 引擎 tick（发送队首/等应答/判超时）、1s 心跳、接收帧状态机、应答精确匹配 |
| `rs485handle.cpp/h`、`tcphandle.cpp/h` | 传输层子类：只实现 `OpenChannel/CloseChannel/WriteData` 三件套，收到原始字节调 `FeedReceivedBytes()` |
| `controlpanel.cpp/h/ui` | 控制面板（一个实例做"控制"，一个做"模式配置"）。按钮互锁、参数读写 ini、组帧并 emit 信号 |
| `controlwidget.cpp/h/ui` | 顶层装配：建立连接(TCP/485)、把 ControlPanel 的信号接到 ConnectiveHandle 的槽、把引擎异常信号转成 QMessageBox |
| `controlsettings.cpp/h` | 通讯/高级设置界面（485 参数、IP 等） |
| `DefaultConfig.ini` | 振动盘 9 个按钮的默认参数（frequency/timeuse/voltage/angle_offset/speed） |

## 3. 线程模型（重要，改动时别破坏）

- `ConnectiveHandle`（及其 RS485/TCP 子类）被 `moveToThread` 到独立工作线程；所有队列、定时器、串口/socket 操作都在该线程内，无跨线程数据访问。
- UI 与引擎之间全部走 Qt 信号槽（跨线程自动排队连接）。
- 断开流程 `CloseConnection()`：先 `disconnect()` 全部信号 → `QThread::finished` 直连 `Shutdown()`（在工作线程内停定时器/关串口）→ quit/wait → 直接 delete（不用 deleteLater，避免事件循环先退出导致泄漏）。

## 4. 通信协议速查（帧格式：55 AA | 指令 | 长度 | 数据 | 校验2B | AA 55）

校验 = 指令起所有字节累加后**取反加一**（16 位，高字节在前）。数据域为空时按公式算出来自然是 0x00 0x00 之外的 0xFFxx——注意 docx 里"长度为 0 时校验为 0"的说法与心跳示例(FF FF)矛盾，**实现以示例为准**（两字节补码），上位机/下位机两端必须一致。

| 指令 | 码 | 长度 | 数据域 | 应答 | 超时策略 |
|---|---|---|---|---|---|
| 心跳 | 01 | 0 | 无 | 02 | 1s，**超时视为断连**，清队列+关连接 |
| 振动盘运动 | 03 | 11(十进制) | 索引1B+电压×10 2B+频率×10 2B+时间s×10 2B+角度偏移2B+速度系数2B | 04(索引+0x01) | **时间×100ms + 2000ms 冗余**（运动完成才回） |
| 振动盘停止 | 05 | 0 | 无 | 06 | 1s；入队时清空运动队列并发 terminate |
| 料仓运动 | 07 | 7 | 索引1B(固定0x01)+电压×10 2B+频率×10 2B+时间s×10 2B | 08(索引+0x01) | 同振动盘：**时间×100ms + 2000ms**（数据域布局一致，[9][10] 即时间域） |
| 料仓停止 | 09 | 0 | 无 | 0A | 1s；入队时清空料仓运动队列并发 terminate |
| 开光源 | 0B | 4 | 索引1B(1=A,2=B)+亮度1B(0~100)+保持时间s×10 2B | 0C(仅索引1B) | **1s**（要求开启后 1s 内收到完成反馈） |
| 关光源 | 0D | 0 | 无 | 0E（A/B 共用同一应答帧，无索引） | 1s |

多字节整数均为**大端**。所有数值字段都 ×10 后取整发送（电压/频率/时间/速度）。

### 超时常量位置
`ConnectiveHandle.cpp` 顶部宏：`ENGINE_TICK_MS=10`、`HEART_BEAT_PERIOD_MS=1000`、`HEART_BEAT_TIMEOUT_MS=1000`、`STOP_MOTION_TIMEOUT_MS=1000`、`BIN_STOP_TIMEOUT_MS=1000`、`LIGHT_RESPOND_TIMEOUT_MS=1000`、`RECV_PARSE_TIMEOUT_MS=2000`（接收半帧超时复位状态机）。

## 5. 一条指令的完整生命周期（以料仓运动为例）

1. 用户点 `pbBinStartMotion` → `ControlPanel::on_pbBinStartMotion_clicked()`：从 `dspbBinVoltage/Frequency/Time` 取值 → `m_pProtocol->BinMotionProtocol()` 生成 (发送帧, 期望应答帧) → `emit sigBinMotion(...)` → 禁用开始、使能停止按钮；
2. `ControlWidget::SetConnectSlot()` 里预建的连接把信号投递到工作线程的 `ConnectiveHandle::SendBinMotionCommand()`：入 `SendCmdType::BinMotion` 队列，超时 = 帧[9][10]×100+2000；
3. 10ms 引擎 `OnEngineTick()`：队首未发则 `WriteData()`（写失败下个 tick 重试）；已发则等 `bRespond` 或超时；
4. 下位机回帧 → 子类 readyRead → `FeedReceivedBytes()` 状态机组帧 → `RecvMessageHandle()` 与各队列队首的期望应答做**全帧字节精确比对** → 置 `bRespond=true`；
5. 下个 tick 引擎弹 出队首并 `emit sigMotionTerminate()` → ControlPanel 的 lambda 恢复全部按钮（振动盘/料仓/光源统一回到空闲态）；
6. 超时路径：`emit sigBinMotionRespondUnnormal()` → ControlWidget 弹"料仓反馈超时" → `OnConnectiveUnnormal()` 末尾统一 `emit m_pControlWidget->sigMotionTerminate()` 恢复按钮。

注意：**振动盘运动、料仓运动、光源开关是相互独立的队列，可同时在途**（光源与振动可并行）；同类型指令内部串行（队列 FIFO）。

## 6. UI 按钮互锁约定（ControlPanel）

- 构造函数里 `sigMotionTerminate` 的 lambda 是**唯一的统一恢复点**：恢复振动盘(发送/停止)、料仓(开始/停止)、光源 A/B(开/关) 全部按钮到空闲态。任何"完成/超时/停止/断连"最终都汇到这里。
- 料仓：开始→禁开始/使停止；停止由引擎清队列后发 terminate 恢复。
- 光源：开→禁开/使关（乐观置位，1s 内没收到反馈会经 unnormal 信号恢复）；关→使开/禁关。关光源应答帧无索引，A/B 共用，超时提示不区分路数。

## 7. 如何新增一条指令（checklist）

1. `generalprotocol.h`：加 `u8SW_XXX_CMD` / `u8FW_XXX_RESPOND` 常量；
2. `ProtocolHandle.h`：加虚函数（给默认空实现，避免破坏可编译性）；`GeneralProtocol` override 实现组帧（发送帧 + 期望应答帧成对生成，走 `AddCheckSum`）；
3. `ConnectiveHandle.h/.cpp`：`SendCmdType` 加枚举 → 队列 map 初始化 → 加 `SendXxxCommand()` 槽 → `OnEngineTick()` 加该队列的处理块（发送/应答/超时三段）→ `RecvMessageHandle()` 加匹配分支 → 需要界面感知的异常加 `sigXxxRespondUnnormal` 信号；
4. `controlpanel`：加 UI 槽（组帧 + emit + 按钮互锁），信号加到头文件；
5. `controlwidget.cpp` 的 `SetConnectSlot(true)`：连接信号槽；`OnConnectiveUnnormal()`：加异常分支（弹窗文案 + 统一 terminate）；
6. `doc/通信协议.docx` 与本文件同步更新。

## 9. 已知怪癖与坑（改动前必读）

- `pbCloseLihgtB`（Lihgt）是 ui 文件里的历史拼写，槽名必须与它一致，不要"顺手修正"；
- 协议 docx 里运动指令"数据长度 11"是十进制 11 字节（不是 0x11=17）；料仓帧是 7 字节；
- 应答匹配是**全帧字节比对**（含校验），所以期望应答帧必须与下位机实际发送逐字节一致；下位机校验算法若与"取反加一"不符会静默匹配失败→超时；
- 运动类超时公式依赖帧内偏移 `[9][10]` 为时间域（振动盘与料仓布局恰好一致），若改数据域布局必须同步改 `Send*MotionCommand`；
- docx"长度为 0 时校验为 0"与心跳示例矛盾，见第 4 节说明；
- 心跳超时是**断连级**异常（关连接、清所有队列），不要把普通业务超时接到 `sigHeartBeatUnnormal`；
- `controlpanel.cpp` 构造函数中 `ui->setupUi(parent)` 传的是 parent 而非 this（历史写法），当前可用，改动 UI 归属时留意。
