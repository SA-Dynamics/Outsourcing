## 1. 项目是什么

柔性视觉供料系统的**上位机**（Qt Widgets 桌面程序），通过 **RS485 串口或 TCP(以太网)** 控制下位机完成三类动作：

1. **振动盘运动**：9 种动作（上/下/左/右/聚拢/水平居中/垂直居中/振散/翻面），由按钮参数（电压/频率/时间/角度偏移/速度系数）驱动；
2. **料仓运动**：电压/频率/时间三参数，语义与振动盘一致——**下位机运动完成后才回帧**；
3. **光源控制**：A/B 两路光源，各自有亮度(0~100)与保持时间，**开启后 1s 内必须收到下位机完成反馈**。

下位机固件在同仓库 `FlexControlSTM32/` 子目录（STM32F103C8/B + W5500 以太网，HAL 库，MDK-ARM 工程），应用层在 `FlexControlSTM32/Application/`（FlexControl / MotorControl / BinControl / LightControl / Network / SerialHandle / Timer / W5500）。主循环 `FlexControlHandle()` = `SerialRecvInfoHandle()`（分发解析后的指令）→ `SerialDataHandle()`（串口收发状态机）→ `MotorControl()` / `BinControl()` / `LightControl()`（三个非阻塞 FSM）。

### 下位机框架约定（仿 MotorControl 模式）

- **指令入口**：`SerialHandle.c::ParseUartData()` 按指令码识别帧（0x01/03/05/07/09/0B/0D），解析进 `SerialInfo`（共享环形缓冲 `SERIAL_INFO_BUFFER_SIZE=16`），`FlexControl.c::SerialRecvInfoHandle()` 按类型分发到对应模块。
- **模块模式**（MotorControl/BinControl/LightControl 三家一致）：环形队列暂存指令（`SendXxxInfo`/`Get`/`Clear`，队列长度：振动盘 16 / 料仓 4 / 光源 4）→ 主循环非阻塞处理（Motor/Bin 是 GET_INFO → Prepare（算查表参数）→ HANDLE 的 FSM；**Light 没有 FSM**，因为两路光源各自独立状态，改成"排空队列 + 逐路扫描"）→ 完成时调 `__weak` 回调（`CbXxxFinish`），回调在 `FlexControl.c` 实现 → `SendSerialRespond()` 发应答帧。
- **料仓查表驱动（已实装）**：料仓占用 **TIM3_CH1(PA6)=极性P / CH2(PA7)=极性N**，与振动盘单个执行器同一套双极性接法。查表与 MotorControl 共用同一张占空比正弦表 `g_s16DutyTable1Cycle[1600]`（定义在 MotorControl.c，USE_SIN_WAVE 分支，**幅值正好 ±4499 = ARR**）；`PrepareBinMotion` 用与 `PrepareMotion` 相同的公式算 `DutyZoom`/`Span`/`Index`（Q15）：`CCR = 表值 × DutyZoom >> 15`，正半周走 CH1、负半周走 CH2，`Span = 1600×32768 / (1/f/62.5µs)`（10Hz→每 PWM 走 1 个表点，200Hz→走 20 个）。表索引走满 1600 点**回绕继续振**（不像振动盘那样停），直到运动时长到。
- **`BinPwmPulseCallback()` 由 `MotorControl.c` 的 `HAL_TIM_PWM_PulseFinishedCallback()` 转发**：HAL 的脉冲完成回调只能有一处定义，那个回调是现有的总入口（先转发料仓、再遍历振动电机）。**TIM3 与光源共用**：光源 CH3/CH4 是纯电平输出、不开中断，所以不会进这个回调。
- **光源硬件映射**（TIM3 由 CubeMX 配好：PSC=0，ARR=4499，CH1~CH4 全为 PWM 输出、OCPolarity=HIGH）：
  - **光源A(LIGHT1) = TIM3_CH3 = PB0**，**光源B(LIGHT2) = TIM3_CH4 = PB1**；
  - 亮度 0~100 线性折算：`CCR = 亮度 × (ARR+1) / 100 = 亮度 × 45`（0→0 恒低熄灭，100→4500>ARR 恒高满占空比）；
  - **两路完全独立**：各有 `bOn / u8Brightness / u16KeepTime / u32TimerCount`，开关与保持时间计时互不影响；
  - **铁律：不能用 `HAL_TIM_PWM_Stop()` 关灯**——它会 `__HAL_TIM_DISABLE` 整个 TIM3 计数器，而 CH1/CH2 是料仓在用的，会把料仓 PWM 一起停掉。关灯只把该路 CCR 写 0；通道在 `LightControlInit()` 里 `HAL_TIM_PWM_Start` 一次，之后不再启停。
- **光源时序**：点亮成功（CCR 已写入）立即回 0x0C（满足上位机 1s 时限），保持时间（单位 100ms）到自动熄灭并回 0x0E；**保持时间 0 = 常亮**，不自动熄灭。上位机主动关（0x0D）走 `LightControlStop(u8Index)`：索引 1/2 只关该路、0 关全部，并丢弃队列中该路排队中的开启指令（否则关完又被点亮）；未点亮时也回 0x0E。
- **新增下位机指令的 checklist**：SerialHandle.h 扩 `InfoType/RespondType`（必要时扩 `SerialInfo`）→ ParseUartData 加 case + Parse 函数 → SendSerialRespond 加应答（用 `SaveRespondFrame()` 通用组帧）→ 新建/扩展模块（队列+FSM+weak 回调）→ FlexControl.c 接分发/回调/Init/Handle → uvprojx 加文件 → 上下位机联调对帧。

## 2. 源码结构与职责

| 文件 | 职责 |
|---|---|
| `ProtocolHandle.h` | 协议抽象基类（QObject）。定义 `GeneralMotion::MotionParams`（运动索引枚举含 `MotionBin`）+ 各指令的组帧虚函数。新增指令先在这里加虚函数（给默认空实现即可） |
| `generalprotocol.h/.cpp` | 唯一实现类 `GeneralProtocol`（单例）。帧头尾常量、指令码常量、`AddCheckSum`、各协议的"发送帧 + 期望应答帧"成对生成 |
| `ConnectiveHandle.h/.cpp` | **通信引擎**（与传输方式无关）：按指令类型分队列、10ms 引擎 tick（发送队首/等应答/判超时）、1s 心跳、接收帧状态机、应答精确匹配 |
| `rs485handle.cpp/h`、`tcphandle.cpp/h` | 传输层子类：只实现 `OpenChannel/CloseChannel/WriteData` 三件套，收到原始字节调 `FeedReceivedBytes()` |
| `controlpanel.cpp/h/ui` | 控制面板（一个实例做"控制"，一个做"模式配置"）。按钮互锁、参数读写 ini、组帧并 emit 信号 |
| `controlwidget.cpp/h/ui` | 顶层装配：建立连接(TCP/485)、把 ControlPanel 的信号接到 ConnectiveHandle 的槽、把引擎异常信号转成 QMessageBox |
| `controlsettings.cpp/h` | 通讯/高级设置界面（485 参数、IP 等） |
| `DefaultConfig.ini` | 振动盘 9 个按钮的默认参数（frequency/timeuse/voltage/angle_offset/speed） |

## 3. 线程模型（重要，改动时别破坏）

- `ConnectiveHandle`（及其 RS485/TCP 子类）被 `moveToThread` 到独立工作线程；所有队列、定时器、串口/socket 操作都在该线程内，无跨线程数据访问。
- UI 与引擎之间全部走 Qt 信号槽（跨线程自动排队连接）。
- 断开流程 `CloseConnection()`：**开头统一 `ui->tabControl->setEnabled(false)`**（2026-11-02 加），覆盖所有断连路径（心跳丢失/主动断开 TCP/485/连接失败/析构）；然后 `disconnect()` 全部信号 → `QThread::finished` 直连 `Shutdown()`（在工作线程内停定时器/关串口）→ quit/wait → 直接 delete（不用 deleteLater，避免事件循环先退出导致泄漏）。
- `ui->tabControl` 的启用/禁用约定：初始禁用（构造函数）→ 连接成功 `OnConnectiveState(true)` 时启用 → 任何路径走 `CloseConnection()` 时禁用。断连后 `sigMotionTerminate` 恢复 lambda 仍会把 ControlPanel 按钮 `setEnabled(true)`，但因父容器 `tabControl` 禁用，按钮不可点（Qt 行为：父容器禁用时子控件即便 enabled 也不可交互）；下次连接成功时 `tabControl` 重新启用，按钮立即可点。

## 4. 通信协议速查（帧格式：55 AA | 指令 | 长度 | 数据 | 校验2B | AA 55）

校验 = 指令起所有字节累加后**取反加一**（16 位，高字节在前）。数据域为空时按公式算出来自然是 0x00 0x00 之外的 0xFFxx——注意 docx 里"长度为 0 时校验为 0"的说法与心跳示例(FF FF)矛盾，**实现以示例为准**（两字节补码），上位机/下位机两端必须一致。

| 指令 | 码 | 长度 | 数据域 | 应答 | 超时策略 |
|---|---|---|---|---|---|
| 心跳 | 01 | 0 | 无 | 02 | 1s，**超时视为断连**，清队列+关连接 |
| 振动盘运动 | 03 | 11(十进制) | 索引1B+电压×10 2B+频率×10 2B+时间s×10 2B+角度偏移2B+速度系数2B | 04(索引+0x01) | **时间×100ms + 2000ms 冗余**（运动完成才回） |
| 振动盘停止 | 05 | 0 | 无 | 06 | 1s；入队时清空运动队列并发 terminate |
| 料仓运动 | 07 | 7 | 索引1B(固定0x01)+电压×10 2B+频率×10 2B+时间s×10 2B | 08(索引+0x01) | 同振动盘：**时间×100ms + 2000ms**（数据域布局一致，[9][10] 即时间域） |
| 料仓停止 | 09 | 0 | 无 | 0A | 1s；入队时清空料仓运动队列并发 terminate |
| 开光源 | 0B | 4 | 索引1B(1=A,2=B)+亮度1B(0~100)+保持时间s×10 2B | 0C(仅索引1B) | **1s**（要求开启后 1s 内收到完成反馈） |
| 关光源 | 0D | 0 或 1 | 无（N=0，关全部）/ 索引1B（N=1，只关指定路，**协议扩展**） | 0E（无索引，A/B 共用同一帧） | 1s |

多字节整数均为**大端**。所有数值字段都 ×10 后取整发送（电压/频率/时间/速度）。

### 超时常量位置
`ConnectiveHandle.cpp` 顶部宏：`ENGINE_TICK_MS=10`、`HEART_BEAT_PERIOD_MS=1000`、`HEART_BEAT_TIMEOUT_MS=1000`、`STOP_MOTION_TIMEOUT_MS=1000`、`BIN_STOP_TIMEOUT_MS=1000`、`LIGHT_RESPOND_TIMEOUT_MS=1000`、`RECV_PARSE_TIMEOUT_MS=2000`（接收半帧超时复位状态机）。

## 5. 一条指令的完整生命周期（以料仓运动为例）

1. 用户点 `pbBinStartMotion` → `ControlPanel::on_pbBinStartMotion_clicked()`：从 `dspbBinVoltage/Frequency/Time` 取值 → `m_pProtocol->BinMotionProtocol()` 生成 (发送帧, 期望应答帧) → `emit sigBinMotion(...)` → 禁用开始、使能停止按钮；
2. `ControlWidget::SetConnectSlot()` 里预建的连接把信号投递到工作线程的 `ConnectiveHandle::SendBinMotionCommand()`：入 `SendCmdType::BinMotion` 队列，超时 = 帧[9][10]×100+2000；
3. 10ms 引擎 `OnEngineTick()`：队首未发则 `WriteData()`（写失败下个 tick 重试）；已发则等 `bRespond` 或超时；
4. 下位机回帧 → 子类 readyRead → `FeedReceivedBytes()` 状态机组帧 → `RecvMessageHandle()` 与各队列队首的期望应答做**全帧字节精确比对** → 置 `bRespond=true`；
5. 下个 tick 引擎弹 出队首并 `emit sigMotionTerminate()` → ControlPanel 的 lambda 恢复全部按钮（振动盘/料仓/光源统一回到空闲态）；
6. 超时路径：`emit sigBinMotionRespondUnnormal()` → ControlWidget 弹"料仓反馈超时" → `OnConnectiveUnnormal()` 末尾统一 `emit m_pControlWidget->sigMotionTerminate()` 恢复按钮。

注意：**振动盘运动、料仓运动、光源开关是相互独立的队列，可同时在途**（光源与振动可并行）；同类型指令内部串行（队列 FIFO）。

## 6. UI 按钮互锁约定（ControlPanel）

- **所有按钮的 clicked 都必须手动 connect**（`setupUi(parent)` 使自动连接失效，详见第 9 节）。漏连 = 按钮可点但无任何反应。
- 构造函数里 `sigMotionTerminate` 的 lambda 是**唯一的统一恢复点**：恢复振动盘(发送/停止)、料仓(开始/停止)、光源 A/B(开/关) 全部按钮到空闲态。任何"完成/超时/停止/断连"最终都汇到这里。该 lambda **开头有 `if (m_bReadOnly) return;`**，防止把只读面板的按钮"恢复"成可点。
- 料仓：开始→禁开始/使停止；停止由引擎清队列后发 terminate 恢复。
- 光源：开→禁开/使关（乐观置位，1s 内没收到反馈会经 unnormal 信号恢复）；关→使开/禁关。**关光源现在带索引（`LightOffProtocol(u8Index,...)`）：点"关 A"只关 A，不再连坐 B**；应答帧 0x0E 无索引，两路共用，故超时提示不区分路数。

### 配置持久化（ini）

- 振动盘 9 个按钮：`[MotionXxx]` 组（frequency/timeuse/voltage/angle_offset/speed）。
- 料仓：`[BinMotion]` 组（voltage/frequency/timeuse）；光源：`[LightA]`/`[LightB]` 组（brightness/timeuse）。
- 三个入口必须同步维护：`SaveSettings()`（写全部组）、`GetSettingParams()`（读，键缺失时回落到控件当前值）、`CopyButtonParams()`（模式↔控制互拷，直接拷 spinbox 值）。**新增任何可保存的 UI 参数，三处都要加**。
- `CopyButtonParams()` 的两条铁律（2026-10-29 修过 bug 的教训）：
  1. **禁止 `m_lstMotionButtons = other.m_lstMotionButtons` 整表赋值**——会把对方面板的 `pButton` 指针拷过来，本面板运动按钮从此选不中；必须按 `qstrName` 匹配逐按钮拷 `qlstMotionParams`；
  2. **UI 全量刷新所有按钮参数时必须用 `QSignalBlocker` 屏蔽 valueChanged**——运动参数控件组只有一套，刷新循环里 `setValue` 会触发槽，槽把遍历值写进选中按钮的存储参数（数据污染）；屏蔽后最终界面停留为最后一个按钮的值，存储数据不受影响。
- `NewSettings()` 以 `DefaultConfigRaw.ini` 为模板复制（该文件不在仓库时 QSettings 落空），`SaveSettings(QString)` 先复制当前文件再全量重写。仓库里的 `DefaultConfig.ini` 已含 `[BinMotion]/[LightA]/[LightB]` 默认段。

## 7. 如何新增一条指令（checklist）

1. `generalprotocol.h`：加 `u8SW_XXX_CMD` / `u8FW_XXX_RESPOND` 常量；
2. `ProtocolHandle.h`：加虚函数（给默认空实现，避免破坏可编译性）；`GeneralProtocol` override 实现组帧（发送帧 + 期望应答帧成对生成，走 `AddCheckSum`）；
3. `ConnectiveHandle.h/.cpp`：`SendCmdType` 加枚举 → 队列 map 初始化 → 加 `SendXxxCommand()` 槽 → `OnEngineTick()` 加该队列的处理块（发送/应答/超时三段）→ `RecvMessageHandle()` 加匹配分支 → 需要界面感知的异常加 `sigXxxRespondUnnormal` 信号；
4. `controlpanel`：加 UI 槽（组帧 + emit + 按钮互锁），信号加到头文件；**并在构造函数"连接按钮事件"段手动 `connect(ui->pbXxx, SIGNAL(clicked()), this, SLOT(on_pbXxx_clicked()))`——本类因 `setupUi(parent)` 导致自动连接失效，漏这一行按钮就是死的（见第 9 节）**；
5. `controlwidget.cpp` 的 `SetConnectSlot(true)`：连接信号槽；`OnConnectiveUnnormal()`：加异常分支（弹窗文案 + 统一 terminate）；
6. `doc/通信协议.docx` 与本文件同步更新。

## 9. 已知怪癖与坑（改动前必读）

- **TIM3 被三个模块共用**，改动前先明确通道归属：CH1/CH2 = 料仓（PA6/PA7，双极性振动，走 CC 中断查表）；CH3/CH4 = 光源A/B（PB0/PB1，纯电平）。
  - 由此产生三条铁律：①**任何模块都不许调用 `HAL_TIM_PWM_Stop()/Stop_IT()`**（见 `stm32f1xx_hal_tim.c:1690`，结尾 `__HAL_TIM_DISABLE(htim)` 关掉 CEN，把另两个模块的输出冻死）；②起停通道优先手动操作 `CCxE`/`CCxIE`/`CCR`，计数器只用 `__HAL_TIM_ENABLE`；③关输出只用 `CCR=0`，不要动 `CCxE`。
  - **料仓的起振改用 HAL 的 `HAL_TIM_PWM_Start_IT()`（2026-10-30，开关 `BIN_USE_HAL_START_IT`）**。它可用，但有两个硬约束：`Start_IT` 在 `stm32f1xx_hal_tim.c:1552` 判断 `ChannelState != READY` 就直接 `return HAL_ERROR`（不写寄存器、不打日志），所以调用前必须 `TIM_CHANNEL_STATE_SET(..., READY)`；而复位状态**不能**用 `Stop_IT`，只能在 `BinPwmStop()` / `BinSwitchChannel()` 里手工写 READY。**两者配对才能重复启停，缺一必出现"第一次能振、之后怎么点都不动"。**
- **`MotorControl()` 末尾原来每轮写 `__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_3, u16PwmLED)`**（`u16PwmLED` 恒为 0 的调试残留），而 CH3 现在是光源A 的亮度通道——已在 2026-10-29 删除。若日后又出现"灯亮了立刻灭"，先查有没有别处每轮写 CCR3。
- **`sMotor[4]` 是料仓的硬件映射但 `pActivePolarity` 从未初始化（NULL）**：`HAL_TIM_PWM_PulseFinishedCallback` 的遍历已从 `i<5` 改为 `i<4`。若改回 5，会解引用空指针，并且和 BinControl 抢写同一个 CCR。
- **停止指令必须复位状态机**：`BinControlStop()` 里 `g_eBinStep = BIN_STEP_GET_INFO`。否则 `pControlFunc` 已置 `BinMoveNone`（立即返回 true），下一轮主循环会误发一帧"运动完成"0x08。
- **⚠️ 料仓"点了没振动"的头号原因：运动时长为 0**（2026-10-30 复算确认）。`PrepareBinMotion()` 里起振与否的**唯一判据**是 `if (u32TimeUseMs > 0) BinPwmStart();`，而 `u32TimeUseMs = fTimeUse * 1000`。`DefaultConfig.ini` 的 `[BinMotion] timeuse=0`、UI 里 `dspbBinTime` 也没设默认值（QDoubleSpinBox 默认 0.0）→ **默认下发的一定是 0** → 不起振、不使能、不写 CCR，下一次 `BinRun()` 直接判完成并回 0x08；上位机因立刻收到应答**不会报超时**，表现为"一切正常但就是不振动"。
  - 排查第一件事：把上位机面板的「时长」设成非零（单位**秒**，如 3.0）再试。
  - 参考占空比峰值：`DutyZoom = V/24*32768`，V=10 → 峰值占空比 1875/4499 ≈ **41.7%**；V=24 → 满占空比。
